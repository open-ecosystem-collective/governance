# Maintainers
 
This file lists the current Maintainers and Stewards of the
`governance` repository of the Open Ecosystem Collective.
 
Maintainers are members at Level 4 or above who carry repository-level
responsibility. Stewards (Level 5) carry cross-repository responsibility
in addition.
 
See [`maturity-levels.md`](maturity-levels.md) for the definitions and
[`CHANGELOG.md`](CHANGELOG.md) for the version history of this and other
governance documents.

## How to become a Maintainer
 
Maintainer status is granted, not requested. The process is documented
in [`maturity-levels.md`](maturity-levels.md) under "Maintainer
responsibilities, in detail." In short:
 
1. You must already be Level 4 or above on the client side
2. A current Maintainer or Steward nominates you
3. Lazy Consensus (72 hours) among existing Maintainers and Stewards
4. Once approved, you are added to this file with your area of
   responsibility
The full criteria, expected duties, and stepdown process are in
`maturity-levels.md`.

## What Maintainers do
 
* Review and merge pull requests in this repository
  (target: 7 days for substantive PRs, 48 hours for typo fixes)
* Triage incoming issues (labelling, clarifying, closing duplicates)
* Hold at least one office hour per quarter for this repository
* Draft the changelog entry for any release
* Update the README when major structural changes happen
* Identify and prepare successor Maintainers

## Reporting concerns
 
If you have a concern about a Maintainer's conduct or a decision they
made, follow the path described in
[`decision-making.md`](decision-making.md):
 
1. Raise it directly with the Maintainer first
2. If unresolved, bring it to the Stewards as a group
3. If still unresolved, open a public discussion (Issue or Discussion)
   so the collective can weigh in
Resolution is sought through conversation. Only in extreme cases does
this lead to a status review.
